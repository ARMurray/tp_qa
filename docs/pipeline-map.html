How it fits together

Three subsystems. detection/ and review_app/ run on the local workstation; correction/ runs on the HPC. Nothing moves between the two machines automatically — every transfer is a deliberate file copy.

The branch that costs the most to get wrong

Retraining the detector is optional on any given pass. But a new best.pt makes every existing detection output stale — 01b, 01c and 01e all have to re-run before 02_feature_engineering, or the feature tables silently mix outputs from two different models.

check_od_freshness.py exists to catch exactly this. Run it. It is the cheapest step in the pipeline and the one that prevents the most expensive kind of mistake.
